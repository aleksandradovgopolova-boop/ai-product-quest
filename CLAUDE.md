## AI Ops — как применять кит (читать ПЕРВЫМ)

Репозиторий подключён к AI Ops (control plane: изолированный worktree, детерминированные гейты, evidence на
точном SHA, независимый ревьюер, strict security #5). **ПРАВИЛО для Claude Code:**

- Когда пользователь просит **изменение кода** (фича/фикс/рефактор — то, что меняет файлы и идёт в PR),
  НЕ правь файлы напрямую. Запусти движок кита:
  **`./ai-run "<дословный запрос пользователя>" [QUICK|ENGINEERING|PRODUCT]`** (по умолчанию ENGINEERING),
  затем доложи результат (гейты, `ready_for_pr`, где остановилось — обычно security **#5 = человек**).
- Прямая правка идёт МИМО гейтов → **нет гарантий кита** (0 false-green, evidence на SHA, независимое ревью).
  Так теряется смысл кита. Прямую правку допускай только для: вопросов/чтения, тривиальных
  не-продуктовых правок (опечатка в README), и того, что пользователь ЯВНО просит «без кита».
- Security #5 (strict) закрывает **ЧЕЛОВЕК** (ApprovalRecord) — агент себе security не одобряет.
- Это **soft-правило** (напоминание, не жёсткий блок): сомневаешься гейтовать или нет — гейтуй через
  `ai-run` или спроси. Мягкий hook `.claude/hooks/ai-ops-guard.sh` напомнит при прямой правке исходников.
