# Бланк наблюдателя — Chapter 01

Один бланк на одного участника. Копировать перед каждым прохождением, заполнять от руки или в файле.

Критерии, пороги и вопросы — из `docs/product/chapter-01-validation.md`. Здесь только то, что заполняется во время сессии.

**Три правила**

1. Во время прохождения наблюдатель молчит. Не подсказывает, не подтверждает, не реагирует на выбор. Единственные слова — заранее заданные вопросы.
2. Записывать сказанное, а не своё толкование. Оценка ставится после интервью, в отдельном блоке внизу. Пока человек говорит — только цитаты.
3. Оценивать до конца интервью нельзя: услышав ответ на вопрос 2, легко «дослышать» его же в ответе на вопрос 5.

## Оценка наблюдателя

Заполнять после интервью, по цитатам выше. Каждое поле переносится в манифест когорты один в один.

### `explainedPrinciple` — вопрос 2, учебный результат 1

☐ да ☐ нет

Засчитывается: человек своими словами говорит, что уверенный тон ответа не означает доступа к фактам — модель продолжила текст, а не проверила его.

Не засчитывается: пересказ сюжета без принципа; «модель ошиблась» без объяснения, в чём; повтор формулировки из главы наизусть.

### `justifiedDecision` — вопрос 4, учебный результат 4

☐ да ☐ нет

Засчитывается: обоснование опирается на обстоятельства ситуации — источников нет, проверить нечем, цена ошибки высокая.

Не засчитывается: «так правильно», «в игре это был верный вариант», ссылка на правило вместо ситуации.

### `mechanismsNamed` — вопрос 4, учебный результат 3

Число: ☐ 0 ☐ 1 ☐ 2 ☐ 3+ (порог — не менее двух)

Считаются названные своими словами механизмы, которых не хватало:

- источники под ответом, ссылки на документы;
- трассировка — видно, откуда взят ответ;
- проверка человеком перед выпуском;
- актуальность источника, срок годности данных;
- явный признак «данных нет» вместо ответа наугад.

Термин называть необязательно, описание своими словами засчитывается. Одна мысль, сказанная дважды разными словами, — один механизм.

### `transferAnswered` — вопрос 5, главный gate

☐ да ☐ нет

Засчитывается ответ, который **разделяет две вещи**: модель сработала корректно (продолжила данный ей текст) и продукт дефектен (нет актуальности источника и его видимости).

Не засчитывается: назвал только одну сторону; «виновата модель»; «виноват тот, кто писал промпт» без выхода на продукт; ответ после подсказки наблюдателя.

Подсказка любого объёма аннулирует ответ. Порог сформулирован как «без подсказки».

### `wantsNextChapter` — вопрос 6

☐ да ☐ нет

Засчитывается прямое «да». «Может быть», «если будет время», «наверное» — это не да.

```json
{
  "participant": "P_",
  "role": "",
  "chapterVersion": "",
  "save": "./run-0_.json",
  "interview": {
    "transferAnswered": false,
    "explainedPrinciple": false,
    "justifiedDecision": false,
    "mechanismsNamed": 0,
    "wantsNextChapter": false
  }

```

Когда собраны все восемь:

```bash
npm run report:cohort -- ./runs/cohort.json
```

## Что искать при разборе, а не при заполнении

Первые пять прохождений разбираются не по средним оценкам, а по повторяющимся точкам непонимания: в каком месте ломается объяснение и на каком шаге. Цитаты из блоков выше — основной материал для этого, отметки «да/нет» — вторичный.

Признаки провала перечислены в `docs/product/chapter-01-validation.md`, раздел «Что считается провалом». Каждый из них означает правку содержания главы, а не полировку интерфейса.
